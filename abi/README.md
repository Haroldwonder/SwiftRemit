# SwiftRemit Contract ABI / Interface Definitions

This directory contains versioned ABI (Application Binary Interface) specifications for the
SwiftRemit Soroban smart contract. Downstream consumers — the TypeScript SDK, the API service,
and third-party integrators — should build against the committed spec in this directory rather
than inferring the interface at runtime.

## Files

| File | Contract version | Status |
|------|-----------------|--------|
| `swiftremit-v1.json` | 0.1.x | **Current** |

## ABI JSON Schema

Each ABI file is a JSON document with the following top-level keys:

```jsonc
{
  "schema_version": "1.0.0",     // ABI schema format version
  "contract_name": "swiftremit", // Package name in Cargo.toml
  "contract_version": "0.1.0",   // Cargo.toml [package].version
  "soroban_sdk_version": "...",   // soroban-sdk dependency version
  "generated_at": "...",         // ISO-8601 timestamp of last generation
  "source": "src/lib.rs",        // Entry-point source file
  "functions": [...],            // Public contract functions (see below)
  "types": {...},                // ContractType definitions used in signatures
  "events": [...]                // Events emitted by the contract
}
```

Each `functions` entry describes a public function:

```jsonc
{
  "name": "create_remittance",
  "doc": "...",
  "inputs": [
    { "name": "sender", "type": "Address" },
    ...
  ],
  "outputs": [{ "type": "Result<u64, ContractError>" }],
  "access": "sender_auth"   // "open" | "readonly" | "admin" | "sender_auth" | "agent_auth" | "integrator"
}
```

## Versioning Policy

SwiftRemit follows **Semantic Versioning** for the contract ABI:

| Change type | Version bump | ABI file action |
|-------------|-------------|-----------------|
| Bug fix with no signature change | Patch (`0.1.0 → 0.1.1`) | Update `contract_version` in existing file; no rename |
| New function/event added (backward-compatible) | Minor (`0.1.0 → 0.2.0`) | Update existing file; add entry to changelog |
| Function renamed, removed, or signature changed | Major (`0.1.0 → 1.0.0`) | **New file** `swiftremit-v2.json`; old file retained |

**Key principles:**

1. **ABI files are never deleted.** Old versions are retained so integrators can pin to a known spec.
2. **Signatures are immutable once released.** Once a function appears in a released ABI, its name
   and parameter types cannot change without a major-version bump and a new file.
3. **The `generated_at` field** is updated on every CI regeneration so downstream consumers can
   detect whether the committed spec is stale.
4. **The committed file is the ground truth.** CI regenerates the spec from the WASM build and
   fails the pipeline if the output differs from the committed file (see `publish-abi.yml`).

## Deprecation Policy

When a function is deprecated:

1. Add a `"deprecated": true` and `"deprecated_since": "vX.Y.Z"` field to the function entry in
   the ABI JSON.
2. Update the function's `"doc"` string to mention the replacement.
3. The deprecated function remains callable on-chain until the next major version.
4. The major-version ABI file that removes the function marks its removal in the changelog.

Example:

```jsonc
{
  "name": "old_function",
  "deprecated": true,
  "deprecated_since": "0.3.0",
  "doc": "Deprecated since 0.3.0. Use new_function instead.",
  ...
}
```

## Regenerating the ABI

The ABI is automatically regenerated by CI on every tagged release. To regenerate locally:

```bash
# Build the contract WASM
cargo build --target wasm32-unknown-unknown --release

# Export the interface spec via Stellar CLI (requires stellar CLI >= 25.3.1)
stellar contract inspect \
  --wasm target/wasm32-unknown-unknown/release/swiftremit.wasm \
  --output xdr-base64-array \
  > /tmp/xdr_entries.txt

# Or use the publish script with a deployed contract ID
./scripts/publish-abi.sh <CONTRACT_ID> testnet
```

The `scripts/publish-abi.sh` script writes the generated spec to
`abi/swiftremit.contract.json`. To produce the versioned `swiftremit-vN.json`, update the
version constant in the script and re-run.

## CI Enforcement

Two CI jobs enforce ABI hygiene:

1. **`check-abi-drift`** (in `publish-abi.yml`) — runs on every PR targeting `main`. It
   rebuilds the WASM, regenerates the spec, and fails if the output differs from the committed
   `abi/swiftremit-v1.json`. This prevents merging a contract change without updating the ABI.

2. **`publish-abi`** — runs on release tags (`v*.*.*`). It regenerates the spec, commits the
   updated ABI file, and uploads the file as a release artifact for archival.

## Changelog

### v1 (`swiftremit-v1.json`) — 2026-07-28

Initial committed ABI for SwiftRemit `0.1.0`. Covers all public functions, types, and events
as of this release, including:

- Core remittance lifecycle: `create_remittance`, `confirm_payout`, `cancel_remittance`
- Batch operations: `batch_create_remittances`, `process_expired_remittances`
- Fee management: `update_fee`, `set_fee_corridor`, `get_fee_corridor`, `calculate_fee_breakdown`
- Oracle integration: `set_oracle`, `get_oracle` (SR-022)
- Administrative: `initialize`, `register_agent`, `remove_agent`, `withdraw_fees`, `emergency_pause`, `unpause`
- Dispute resolution: `raise_dispute`, `resolve_dispute`
- Health and query: `health`, `get_remittance`, `get_accumulated_fees`, `get_remittance_count`, `get_total_volume`
